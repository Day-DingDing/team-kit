# 공통 규칙 (모든 팀원)

## 범위
- 수용 기준은 **최대 `team.json`의 `ac_max`개(기본 30)**. 작은 프로젝트는 10~15개로 줄인다. 넘으면 우선순위가 낮은 것을 "다음 범위"로 뺀다. (시범에서 기획이 70~93개로 넓히는 경향이 확인됨)
- 원문(`00-requirements.md`)에 없는 기능은 추가하지 않는다. 필요하면 총괄에게 제안한다.

## API·데이터 형식 (요구사항에서 따로 정하지 않으면 이 기본값)
- 필드 이름은 `snake_case`. 날짜는 `YYYY-MM-DD`, 시각은 ISO 8601(UTC).
- 값이 없으면 `null` (빈 문자열 `""` 쓰지 않음).
- 오류 응답: `{"error": {"code": "<영문 코드>", "message": "<한국어 설명>"}}`. 상태 코드: 잘못된 입력 400, 없음 404, 허용 안 된 메서드 405.
- **모르는 필드가 오면 400으로 거부**한다 (조용히 무시하면 필드 이름 오타로 데이터가 빠져도 모른다).
- 바꿀 내용이 없는 수정 요청은 400.

## 실행 환경
- 테스트·보안·준법 재확인은 **운영과 같은 런타임**(컨테이너 이미지의 언어 버전)에서도 실행한다. 개발 PC 버전과 다르면 결과에 두 환경을 모두 적는다. 다른 런타임에서만 확인했으면 "통과"가 아니라 "다른 런타임(버전)에서 통과"로 쓴다. (2차 시범: 3.14에서만 확인해 출시 직전 3.12에서 실패 발견)

- 테스트 하네스는 처음부터 운영 런타임 컨테이너에서도 돌 수 있게 만든다. 컨테이너·서버·임시 파일 이름에는 자기 역할 접두를 붙이고, 정리할 때는 그 이름만 지운다.
- **프로세스 종료는 자기가 띄운 PID만** 한다. `pkill`/`killall`은 쓰지 않는다(다른 역할의 서버와 자기 셸까지 종료된 사례가 있음). headless Chrome은 역할마다 별도 `--user-data-dir`를 쓴다.

## 보안·준법 기본값
- 비밀값은 코드·저장소에 넣지 않는다 (환경 변수, `.env`는 git 제외). 로그에 개인정보·비밀값을 남기지 않는다.
- 오류 응답에 내부 경로·스택 정보를 넣지 않는다. 요청 본문 크기 상한을 둔다.
- 개인정보는 필요한 항목만 수집하고, 수집하면 목적·보관 기간·파기 방법을 요구사항에 적는다.
- 외부 패키지·글꼴·이미지를 쓰면 라이선스를 기록한다.
- 제한·상한(요청 횟수, 잠금, 크기)을 넣을 때는 **한 사용자가 그 한도를 다 쓰면 다른 사용자가 어떻게 되는지** 시험한다 (예: 전역 잠금에 담당자도 걸림).

## 화면
- 색·글꼴·간격은 `docs/03-design/tokens.css`의 변수만 쓴다.
- 모바일(360px)과 데스크톱(1280px) 폭에서 가로 스크롤이 없어야 한다. headless Chrome의 창 폭 지정이 정확하지 않으므로, 360px 판정은 그 폭의 iframe 하네스 페이지에 앱을 넣어 확인한다.

## 문서 (모든 기록은 문서로, 작성은 본인이)
- 산출물·회의록·결정·버그·작업 기록·회고는 모두 `docs/templates/`의 양식을 따른다. 양식은 사용자만 고친다.
- 작성자 본인이 쓴다. 다른 역할의 문서를 대신 쓰지 않는다. 회의록의 참석자 의견, 회고의 각자 절도 본인이 쓴다.
- 산출물 메타 표: 버전 / 작성자 / 상태(작성 중 → 검토 중 → 확정, 확정 뒤 고치면 "변경됨" → 다시 확정) / 최종 수정 / 관련 결정.
- 고칠 때: Edit로 고치고 버전을 올린다(확정 전 v0.x, 확정 v1.0, 이후 v1.1…). 변경 이력에 `버전 / 날짜 / 작성자 / 내용 / 이유·D-번호`를 덧붙인다. 이미 있는 문서를 Write로 덮어쓰는 것은 훅이 막는다.
- 결정이 바뀌어 다른 문서에 영향이 있으면, 총괄이 해당 작성자에게 개정을 요청한다.
- 작업 기록: `docs/worklogs/<이름>.md`. 작업 하나 끝날 때마다 한 항목.
- 테스트 원본 결과(`reports/test/`, `reports/deploy/`)도 커밋한다. `reports/` 아래는 `*.log`도 커밋된다(.gitignore 예외). 문서의 숫자는 원본과 같아야 한다.
- 완료 전 `python3 tools/check-docs.py`가 실패 0이어야 한다.
